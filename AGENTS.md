# Working agreements

- Keep PRs focused and as small as practical; aim for 200–400 changed lines. Smaller changes are welcome. Split unrelated work.
- Use feature branches and pull requests for implementation. Do not push implementation directly to main or merge without user authorization.
- Keep proprietary game assemblies, saves, credentials, local tools, and build outputs out of Git.
- Distinguish successful builds from in-game verification. Do not claim untested platform support.

## Session continuity

- Read `PROJECT_STATUS.md` at the start of each session before planning or editing.
- Keep it current in each relevant PR and before a handoff: decisions, verified progress, next steps, open issues, fixes, and validation evidence.
- Record proposals separately from agreed decisions and tested facts. Update the date, and verify PR/branch state rather than assuming an old snapshot is current.
- Keep the handoff concise and actionable; link to detailed docs instead of duplicating them. Never record credentials or private raw logs.
